# 加工記録 注記の書式仕様

準拠: ToolLtm v0.13.3 ／ 改訂 r2（2026-10-28、analyzer 側の確認反映）／ 正本: ToolLtm リポジトリ `docs/note-format.md`。analyzer はコピーを持ち、この行の「準拠」と「改訂」で同期を取る。

対象: hyperDENT ログに貼る注記行（`.iso` 行の直後の1行）。ToolLtm と hyperdent-log-analyzer の共通入力。
原則: **ToolLtm のパーサーが厳しい側なので、本書は ToolLtm の挙動をそのまま書く。** analyzer はこの範囲内の語を辞書で分類する。語は足してよいが、§5「書いてはいけない形」に当たる語は足さない。
検証: 2026-10-28 に GitHub main の `index.html`（v0.13.3）を直接実行して確認した結果。

## 1. 正規化（ToolLtm が読む前に行うこと）

| 変換する | 変換しない（そのまま読まれる） |
|---|---|
| 全角数字 `０-９` → 半角、全角スペース → 半角、`＃` → `#` | **全角英字**（`ＴｉＰ`、`Ｃ`、`ｗ２`）、全角記号（`＠`、`：`）、ハイフン類（`−` U+2212 など） |

全角英字は認識されない（材料・マシン・種別・テンプレが全部落ちる）。英字と `#` 以降のハイフンは**必ず半角**。

## 2. 認識する語（フィールドごと）

| フィールド | 語 | 一致規則 | 期待バーへの影響 |
|---|---|---|---|
| マシン | `d1` `d2` `w1` `w2` | 単語として（大小無視）。**注記の語が NC名より優先**。最初に出た1つ | スロット→バー解決に使う |
| 材料 | `TiA` `TiP` `Zr` `Stone` `WAX` `PMMA` `PEEK` `HR` | 単語として（大小無視）。最初に出た1つ。注記に無ければ NC名の `_TiA_` 等のトークン | Stone/WAX/PMMA/PEEK→11/12/16、HR→50/51/52、TiA/TiP→テンプレ次第、Zr→13/14/15 |
| 材料（第2信号） | `CAD` | 単語として。`PEEK` があれば PEEK 優先 | CADCAM→50/51/52 |
| 種別 | `Cr` `In` `On` `Br` `Con` | 単語として、**大文字小文字を区別**（`cr` は不一致）。辞書順 Cr→In→On→Br→Con で最初に当たった1つ | なし（集計軸のみ） |
| 種別 | `石支台` | **部分一致**（どこにあっても） | なし。材料は別途 `Stone`（注記または NC名）が必要 |
| テンプレ | `A` `B` `C` | 単独の大文字1字（直後に数字が無いこと）。**TiA/TiP のジョブのみ**有効。`TiA Br B` の並びは最優先、それ以外は注記中で最初の単独大文字 | A→1/2/4、B→61/62/64、C→66/67/69、無指定→A |
| 戦略 | `long_inside` `Slow` `Normal` | 前後が英数字でなければ一致（`_` は区切り、大小無視）。優先順位はこの順。さらに `何か_v数字`（`insurance_v2` 等）と `insurance…` がこれらより優先。**`Fast` は認識しない**（CAD 系・精度不足で不使用。書いても無視される） | なし（集計軸のみ。保存は原文の大小） |
| 修飾 | `Fissure` | 前後が英数字でなければ一致（大小無視） | **Zr のときだけ** 13/14/33 |
| 歯式 | `#45-47` `#36,37` | `#` の直後の数字・`-`・`,`。最初の1つ | なし |
| 数量 | `全N` `支台N` `ポンN` `前N` `ユN`（正規形）。`支N` `ポN` は略記として ToolLtm が読む（analyzer は v0.4 で別名として受ける） | 語の直後の数字（間に空白可。5つの数に限る） | なし。`全N` は歯数の正 |

マシンの相互チェック: ToolLtm は注記のマシンを採用する。analyzer は NC 出力フォルダ（`NC Output_wet1` 等）と注記を比べて「機械不一致」フラグを出すので、**そのフラグが立った行＝ToolLtm 側で機械を取り違えて登録したジョブの候補**。定期的に突き合わせる。

## 3. 無視される語（足してよい語の例）

ToolLtm が読まない語は何を書いても無害。確認済み: `@h` `@s` `@他社` `@他社:ab` `@技工所:ab` `G4` `松風HARDⅡ` `A3.5`（`A` の直後に数字があるのでテンプレに取られない）`Fast`。
analyzer 側の辞書に入れる語は、§5 に当たらない限り自由。

## 4. 推奨の書き方（両ツールで安全な形）

**語は空白で区切る。** `_` 結合と括弧形は ToolLtm は読めるが、analyzer では1語になり辞書に別語として立つため非推奨。

```
w2 TiP Br C #36-37 全3 前3 支台2 ポン1 ユ10 @h        → w2 / TiP / Br / C / 66,67,69
d2 Zr Br Normal Fissure #23-35 全3                     → Zr / Normal / fissure / 13,14,33
w2 TiP Cr C long_inside #16 全1                        → C / long_inside / 66,67,69
d1 Stone 石支台 #36 全1                                → Stone / 石支台 / 11,12,16
w2 TiP Br C #36-37 全3 G4 @他社:ab                     → G4 と @他社:ab は無視される
```

運用の取り決め（2026-10-28）:
- long_inside は `C long_inside`（空白）。`A_Long_inside` 形は使わない（§5 参照）
- 支台は `Stone 石支台` と両方書く
- 受託は `@他社:コード` または `@技工所:コード`。コードは小文字英数字で、`b`/`s`＋数字、`Cr/In/On/Br/Con`、`d1/d2/w1/w2` を避ける
- 純チタンのグレード4は `G4` を別語で。`TiP4` は書かない
- 担当は `@h` `@s`（小文字）

## 5. 書いてはいけない形（ToolLtm が誤読する）

| 形 | 何が起きるか | 代わりに |
|---|---|---|
| 単独の**大文字** `A` `B` `C`（例 `@A`、担当コード `A`） | TiA/TiP ジョブでテンプレに取られ、期待バーが変わる。`@A` で A 系になるのを確認済み | 担当・コードは**小文字**（`@a` は無害） |
| 大文字始まりの `Cr` `In` `On` `Br` `Con` を別の意味で（例 発注元コード `Cr`、英語の `On`） | 種別が上書きされる（`@他社:Cr` で Br→Cr、`On time` で On になるのを確認済み） | コードは小文字。英単語を書かない |
| **`A_long_inside` / `C_long_inside`（テンプレ字と `_` で結合）** | `_` が単語文字のためテンプレ字が落ちる。A は既定値なので偶然正しいが、**B/C は 1/2/4 に誤る**（確認済み） | `C long_inside`（空白）。v0.14 で結合形も受ける改修は任意（運用を空白区切りに変えたため優先度低） |
| `TiP4` `TiA2` のように材料語に文字を続ける | 材料不明になる（確認済み） | `TiP` は単独、グレードは別の語 `G4` で |
| `何か_v数字`（例 `G_v4`） | テンプレ名として最優先で拾われる | `_v` 数字の形を避ける（`G4` なら無害） |
| `insurance` で始まる語 | テンプレ名に拾われる | テンプレ名以外の意味で使わない |
| `b数字` `s数字`（例 `@他社:b12`） | ブランク／スロット欄に拾われる（期待バーには影響しないが汚れる） | コードに `b`/`s`＋数字を使わない |
| `d1` `d2` `w1` `w2` を別の意味で | マシンが上書きされる（注記のマシンが最優先） | コードに使わない |
| 材料語を別の意味で（`Stone` `HR` `WAX` …） | 最初に出た材料語が採用される | 使わない |
| 単独の2桁数字（`14` `12L` `15XLL`） | ブロックサイズに拾われる（無害だが意図せず入る） | 歯式は `#` の後に書く |
| `石支台` の直後に数字（`石支台 2`） | 支台数に拾われる | 歯数は `全N` で |
| 全角英字・全角記号・`−` | §1 のとおり読まれない | 半角 |

## 6. CSV 突合（analyzer が ToolLtm の加工記録 CSV を読むとき）

- **日付・時刻の由来**: NC名末尾 `_YYYYMMDD_HHMM`。日付は NC名の8桁（無ければ貼り付け時の UI 日付）、時刻は4桁。マシンは注記の語 → NC名の順。
- **鍵**: `日付+時刻+マシン` は**一意でない**（hyperDENT は同じ分に複数の NC を出す）。鍵は **NC名**（v0.13.4 で CSV 列27「NC名」＝`raw`、パスと `.iso` を除いた基底名。患者名は含まれない）。analyzer v0.5 はこの列を前提にする。
- **実測として使う行**: 状態が `ok` `救済` `尻尾`（連結含む）で、かつ **役割1秒〜役割3秒が3つとも入っている行**。`推定` は順序を見ない貪欲一致なので除外。`未突合` `保持期間外` は実測なし。
  - `ok` でも一巡が途中で終わった行がある（日末で仕上げバーの出番が無い等）。v0.13.4 で状態に `部分` が付く（例 `ok+部分`）。付くまでは役割列で判定。
  - `救済` は NC順と加工順が入れ替わったジョブ。別日の未突合ジョブが翌日分を横取りする既知の問題（design-doc §7 未決1）があるため、**予測≫実測の 救済 行は横取りとして analyzer がフラグを出す**（検出器として使う）。
- **合計秒の定義**: 期待バー全部の `used` の和＝役割1秒＋役割2秒＋役割3秒。尻尾秒は役割2秒に含まれ、合計にも含まれる。保持時間（装着→返却）の和であり、バー交換・測定のオーバーヘッドを含み、段取り・ネストは含まない。
- **保持期間**: セグメントは60日のローリング保持。ジョブ行は残るが、60日を過ぎると実測列が空になる。analyzer は保存領域を持たず、**月1回の CSV をファイルとして溜めて一緒に読む**（鍵＝NC名で重複を除く）。ToolLtm 側の凍結（v0.14 候補5）は入れば使うが前提にしない。
