# ToolLtm v0.13.1 実装指示書 — 加工記録のCSV出力

作成: 2026-09-10 ／ 対象: `index.html`（v0.13）＋ `test_v0_13.js`
規模: 小（ボタン1つ・関数2つ・テスト3本）。設計の変更はなし。

---

## 0. 目的と、やらないこと

**目的**: 加工記録（jobs）を1行1ジョブのCSVで出し、Excelのピボットで「日付×種別」の件数・歯数・ユ数・機械時間を集計できるようにする。集計画面はアプリ内に**作らない**（同じピボットを3回手で作ったら検討する、が判断基準）。

**やらないこと**: 集計UI、グラフ、技工士の手作業時間（ToolLtmの外の話）。

## 1. 追加するもの

| # | 項目 | 場所 |
|---|---|---|
| ① | `computeJobMatches(db, list)` — 2パス突合を関数に切り出す | `renderJobs`（L1083〜）の突合ブロック |
| ② | `jobsCsv(db)` — CSV文字列を作る | `exchangesCsv` の隣 |
| ③ | ボタン `加工記録をCSV出力`（id: `btnCsvJobs`） | L175 の `btnCsvEx` の隣 |

### ① computeJobMatches(db, list) → `{ [jobId]: r }`
- `renderJobs` 内の「1パス目→2パス目」のブロックをそのまま関数化し、`renderJobs` はこの関数の結果を描画するだけにする（**画面とCSVで同じ結果になる**ことが目的。二重実装禁止）。
- 戻り値 `r` の形は現行と同じ: `{mt, rescued, outOfRange}`。`mt` は `matchSegments` の戻り（`used`, `picked`, `tail`, `estimated`, `lastEnd`…）。
- CSVでは `list = db.jobs` 全件を `(date+hhmm)` 昇順で渡す。フィルタは掛けない（Excel側で絞る）。

### ② jobsCsv(db) — 列仕様

1行=1ジョブ。ヘッダは以下の順（日本語ヘッダ、既存CSVと同じ流儀）。

| # | 列名 | 値 | 元 |
|---|---|---|---|
| 1 | 日付 | `2026-09-07` | `j.date` |
| 2 | 時刻 | `11:34` | `j.hhmm` を `HH:MM` に |
| 3 | マシン | `d1` | `j.machine` |
| 4 | 種別 | `石膏支台` / `クラウン` / … | `KIND[j.kind]`（辞書外はそのまま） |
| 5 | 材料 | `TiA` / `CADCAM` / 空 | `j.material` |
| 6 | 厚み | `14T` 等 | `j.thick`（なければ空） |
| 7 | テンプレ | `A`/`B`/`C`/空 | `j.template` |
| 8 | テンプレ名 | `insurance_v2` / `long_inside` / `Slow` / 空 | `j.templateName` |
| 9 | 歯式 | `#35-37` | `j.teeth` |
| 10 | 全 | 数値 | `j.units` |
| 11 | 支台 | 数値 | `j.abut` |
| 12 | ポン | 数値 | `j.pontic` |
| 13 | 前 | 数値 | `j.veneer` |
| 14 | ユ | 数値 | `j.userdef` |
| 15 | 期待バー | `11/12/16` | `j.expectedBars.join("/")` |
| 16 | 実消費(バー別) | `11=401;12=1032;16=411` | `mt.used`（**秒**、`;`区切り。監査用） |
| 17 | 役割1秒 | 数値 | `mt.used[E[0]]`（荒・3mm相当） |
| 18 | 役割2秒 | 数値 | `mt.used[E[1]]`（中・2mm相当。尻尾分を含む） |
| 19 | 役割3秒 | 数値 | `mt.used[E[2]]`（仕上・1mm相当） |
| 20 | 尻尾秒 | 数値 | `picked` のうち `tail:true` の `dur` 合計 |
| 21 | 合計秒 | 数値 | `used` 全バーの合計 |
| 22 | 合計 | `00:30:44` | 21 を `secToHms` |
| 23 | 状態 | `ok` / `救済` / `推定` / `尻尾` / `保持期間外` / `未突合` | 下記 |
| 24 | 注記 | 原文 | `j.note`（ダブルクォートで囲む） |
| 25 | 歯数(算出) | 数値 | 下記ルール。**列10「全」は原文のまま残す**（正はあくまで注記の全N） |

**歯数(算出)のルール**（2026-09-11 追加。単冠・支台には全Nが書かれないため、ピボットで歯数合計を出すための派生列）
1. `j.units` があればその値（Br/Con、または全Nを明記した支台）
2. なければ種別で決める: クラウン/インレー/アンレー = **1**、石膏支台 = **1**、連結冠 = `fillUnits` 後の `units`（既に入る）
3. どちらも取れなければ空
- 石膏支台は「別物」だが、ピボットの列軸が種別なので歯数=1で混ざる心配はない。1ジョブに複数の支台をネストした場合は注記に全Nを書く運用（ルール1で拾う）。
- この派生列は**ToolLtmの中で歯数を持つ唯一の場所**にする。可視化プロジェクトや日次報告で歯数を数えるときも同じルールを使う（数え方の不一致を防ぐ）。

**状態の決め方**（複数該当は `+` で連結、例 `救済+尻尾`）
- `outOfRange` → `保持期間外`（17〜22 は空）
- `mt` が null → `未突合`（17〜22 は空）
- `rescued` → `救済`
- `mt.estimated` → `推定`（期待バーが空なので 17〜19 は空、21・22 のみ）
- `mt.tail` → `尻尾`
- 上記いずれでもなければ `ok`

**役割列の意図**: テンプレごとにバー番号は違う（11/12/16、50/51/52、1/2/4、61/62/64、66/67/69）が、**位置=役割**は共通。ピボットで「種別ごとの2mmバー平均時間」のような横断集計をバー番号に依存せず出すための列。

**エスケープ・エンコーディング**: `exchangesCsv` と同じ関数（カンマ・改行・ダブルクォートのクォート、BOM有無も同じ）。数値は素の数字（`"`なし）、空は空文字。ファイル名 `toolltm_jobs.csv`。

### ③ ボタン
- `btnCsvEx` の隣に `<button id="btnCsvJobs">加工記録をCSV出力</button>`。
- ハンドラは `btnCsvEx` と同型: jobs が空なら `dataMsg` に「加工記録がまだ空。」、あれば `download("toolltm_jobs.csv", jobsCsv(db), "text/csv")`。

## 3. Excel 側の使い方（実装対象外・運用メモ）

CSVを開いてピボット: 行=日付（月でグループ）、列=種別、値=「合計/件数」「全 の合計」「ユ の合計」「合計秒 の合計÷3600」。これで **月×種別の 件数・歯数・ユ数・機械時間** が1画面。役割1〜3秒を値に足せば「種別ごとの荒/中/仕上の平均時間」も同じ画面で出る。ピボットを保存しておき、次回はCSVを差し替えて更新するだけ。
